## 2026-08-18：分层记忆运行时发布冻结 / 0.18.0

0.17.1 只有“宿主预取后单次判断，必要时进入旧工具循环”的弱基线，没有统一请求快照、可验证
缓存契约和独立表层输出边界。0.18.0 把生产链路收敛为同一个分层运行时。L0 在请求开始时固定
`RequestSnapshot`：群 scope、严格时间 cutoff、事务内消息行上界、请求/回复来源、发送者以及
数据和推理 revision。后续 SQL、主体解析、图遍历和来源审计都必须落在该快照内，避免同秒新
消息、身份变化或图更新穿透一次正在运行的重建。

历史研究材料不作为当前版本的效果证明。当前线上结论应来自同一真实请求经过检索、Reader、注入与最终回答的完整链路，并同时列出失败与缺失证据。



schema 16 为每个物理群库增加 request snapshot、evidence-pack cache、memory certificate、
certificate dependency 与 reconstruction job 生命周期；启动只收敛不可恢复的悬挂请求，并
有界清理过期缓存、证书和孤立快照。依赖仍是基础 `fastembed==0.8.0`，Harrier 继续使用既有可选
依赖，0.18.0 没有增加包。完整运行时源文件边界见
