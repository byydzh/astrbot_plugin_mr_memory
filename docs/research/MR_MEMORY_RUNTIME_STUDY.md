# MR Memory 运行效果验收方法

本页只公开方法，不携带个人语料。历史真实案例、聊天摘录、查询、称呼、群账号、标准答案和带原文的报告不属于可发布材料。旧实验结果不能证明当前线上版本达到效果要求。

## 一次完整请求

验收保留同一请求的历史截止时间与本群范围，从实际数据库检索开始，依次记录 Reader 调用、宿主校验、实际注入内容和最终可见回答。冻结证据包的合成测试只能验证对应组件，不能替代这条完整链路。

## 同时评估效果、速度与成本

- 效果：人物与非人物指称准确，来源支持实际结论，时间与归因不丢失，保留冲突和不确定性，回答自然且没有内部协议泄露。
- 速度：分别记录检索、首字节、Reader 总时长、编译和主模型回答时间；不能只报告局部耗时。
- 成本：记录真实输入、缓存输入、输出和调用次数；没有账单证据时不虚构货币成本。
- 失败：Provider 不可用、协议失败、预算不足与真实无相关记忆分别统计，不能用有效空结果掩盖失败。

## 证据边界

公开自动测试只使用全新合成数据。真实反面案例与人工验收标准在私有目录分别保存，标准答案不进入生成阶段。先记录完整结果，再按事先确定的标准判定。失败案例、缺失结果和耗时调用都保留在统计中。

字面诊断、来源覆盖和结构校验不等于语义准确率。个人语料的删除只清理当前工作树，不自动清除已经存在的历史提交或外部副本。

## 回放限制

通过真实数据库、插件钩子和已配置 Provider 的私有回放，仍需说明是否还原了 AstrBot 当时的对话历史、人格提示、引用消息和工具执行环境。缺失原图、已删除来源或缺少引用目标的案例不可用合成内容补成通过。未连接播放器或消息适配器的回放不能证明播放或投递成功。

注入完成只代表插件交付了简报。人物绑定、最终回答的事实、预测的不确定性和工具动作都需分别核对；无法识别实际醒来时间时，准确报告每日首条发言仍不等于预测成功。读取来源的时间戳必须保留时区，不能由模型自由换算。

完整时间窗口的宿主统计独立记录范围、原始消息数和来源修订摘要，不用有限摘录冒充全量。提供商返回空正文时，保留原始内容通道长度、结束原因和已观察用量；不读取隐藏推理作为最终决策，也不把缺少用量记录视为免费。
